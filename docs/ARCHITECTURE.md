# Forma — архитектура

AI-воркспейс: база знаний + проектный менеджер с интегрированным агентом.
Упрощённый аналог Notion, но локальный, файловый и с агентом в роли «мозга».

## 1. Принципы

1. **Файлы — источник истины.** Всё содержимое (wiki, задачи, проекты, чаты,
   определения агентов) — это markdown с YAML frontmatter в одной директории
   («vault»). Vault — обычный git-репозиторий: история, диффы, бэкап и
   синхронизация бесплатно. Любая БД — только производный индекс, который можно
   удалить и пересобрать.
2. **Интеллект делегируется агенту, приложение — «глупое».** Forma не содержит
   собственного RAG/LLM-пайплайна. Планирование дня, дистилляция знаний,
   отчёты, ревью — всё это делает подключённый coding-агент (Claude Code через
   Agent SDK, позже Codex), для которого vault — рабочая директория. Forma
   отвечает за хранение, индекс, UI, расписание и доставку контекста агенту.
3. **Расширяемость = MCP + skills + инструкции, не своя плагинная система.**
   Интеграции (почта, календарь, трекер, внутренние API) подключаются как MCP-серверы;
   повторяемые сценарии (план недели, weekly review) — как skills; личный и
   корпоративный контекст — как instruction-файлы. Всё это уже умеет агентный
   рантайм — Forma даёт UI для управления этим.
4. **Everything is a file.** Раз агент работает файловыми инструментами, всё,
   чем он должен управлять, должно лежать файлами: задача — файл, кастомный
   агент — файл, история чата — файл. Это же даёт совместимость с Obsidian
   (vault открывается в нём как есть) и переносимость.
5. **Local-first, single-user.** Никакого облака в MVP. Сервер слушает
   localhost; секреты — в `.env` / macOS Keychain.

## 2. Общая схема

```
┌────────────────────────────────────────────────────────┐
│  forma-web (React + Vite)                              │
│  Дашборды (день/неделя/проекты) · Редактор (TipTap)    │
│  Чат с агентом · Управление агентами · Настройки       │
└───────────────┬────────────────────────────────────────┘
                │ REST + SSE (стриминг агента)
┌───────────────┴────────────────────────────────────────┐
│  forma-server (Node.js / TypeScript)                   │
│                                                        │
│  VaultService     — CRUD над файлами, атомарная запись,│
│                     git-коммиты изменений              │
│  IndexService     — SQLite + FTS5, derived от файлов,  │
│                     file watcher → реиндексация        │
│  AgentRuntime     — сессии агента (Agent SDK),         │
│                     стриминг, permissions, история     │
│  Scheduler        — cron/event-триггеры кастомных      │
│                     агентов, журнал запусков           │
│  IntegrationHub   — реестр MCP-серверов и skills,      │
│                     прокидывание их в AgentRuntime     │
└───────────────┬────────────────────────────────────────┘
                │ файловая система
        ┌───────┴────────┐
        │  Vault (git)   │ ←── агент читает/пишет сюда же
        └────────────────┘
```

Десктоп для macOS — позже, как **Tauri 2**-обёртка: тот же фронтенд,
forma-server запускается sidecar-процессом. Никакого второго кода.

## 3. Vault: формат данных

```
vault/
├── wiki/                  # дистиллированные знания (LLM-wiki слой)
│   ├── index.md           # карта знаний, поддерживается агентом
│   └── arc/vfs-design.md
├── raw/                   # сырьё: логи, выгрузки, заметки со встреч,
│   └── 2026-06-13-meeting-notes.md      # transcripts, clippings
├── projects/
│   └── forma-mvp/
│       ├── project.md     # статус, сроки, цели (frontmatter + текст)
│       └── tasks/
│           └── 0001-setup-vault-format.md
├── inbox/                 # задачи/заметки без проекта, «свалка» для разбора
├── journal/               # daily notes: план дня, итоги, журнал решений
│   └── 2026-06-13.md
├── chats/                 # история диалогов с агентом
│   └── 2026-06-13-planning/
│       ├── transcript.jsonl   # полный лог (события SDK)
│       └── summary.md         # выжимка для накопления знания
├── agents/                # пользовательские агенты
│   └── weekly-report.md   # промпт + триггер во frontmatter
├── reports/               # сгенерированные отчёты
├── .claude/               # контекст для агентного рантайма
│   ├── CLAUDE.md          # личные данные, конвенции, ссылки на wiki
│   ├── skills/            # plan-day, plan-week, weekly-review, distill, ...
│   └── mcp.json           # подключённые MCP-серверы
└── .forma/                # служебное, в .gitignore
    ├── index.db           # SQLite-индекс
    └── runs/              # журналы запусков агентов
```

### Задача — markdown с frontmatter

```markdown
---
id: t-0001
title: Спроектировать формат vault
status: in_progress        # inbox | todo | in_progress | blocked | done | cancelled
project: forma-mvp
priority: high
due: 2026-06-20
scheduled: 2026-06-16      # на какой день запланирована
tags: [architecture]
source: chat:2026-06-13-planning   # откуда взялась (чат, почта, трекер)
created: 2026-06-13
---

Контекст, критерии готовности, заметки — свободный markdown.
Агент дописывает сюда прогресс и ссылки.
```

Тот же паттерн для проектов (`project.md`: статус, дедлайны, цели, риски),
wiki-страниц (`sources:` — ссылки на raw-материалы, из которых дистиллировано)
и агентов (см. §6).

**Почему файлы, а не БД:** агент редактирует их штатными инструментами без
специального API; git даёт историю и устойчивость к ошибкам агента (всё можно
откатить); vault читается Obsidian/любым редактором; нет lock-in.

### Индекс (SQLite + FTS5)

Дашбордам нужны быстрые выборки («задачи на неделю по всем проектам»),
поэтому сервер держит производный индекс: таблицы `documents`, `tasks`,
`projects`, `links` + полнотекстовый поиск. Watcher (chokidar) на vault
переиндексирует изменённые файлы — в том числе те, что поменял агент или
пользователь во внешнем редакторе. Индекс никогда не пишется «вперёд» файлов.

## 4. Агентный слой

### Абстракция провайдера

```ts
interface AgentProvider {
  createSession(opts: SessionOptions): AgentSession;
}
interface AgentSession {
  send(message: UserMessage): AsyncIterable<AgentEvent>; // text/tool_use/permission_request/result
  interrupt(): Promise<void>;
  resume(sessionId: string): Promise<void>;
}
```

- **Провайдер №1 — Claude Agent SDK** (`@anthropic-ai/claude-agent-sdk`,
  TypeScript). Даёт из коробки: файловые инструменты, bash, MCP-клиент,
  skills, subagents, session resume, permission-хуки. Рабочая директория
  сессии — vault.
- **Провайдер №2 (позже) — Codex** через его protocol/SDK; кандидат на общий
  знаменатель — ACP (Agent Client Protocol). Абстракция выше — тонкая,
  чтобы не проектировать «универсальность» раньше времени.

### Режимы работы

| Режим | Запуск | Пример |
|---|---|---|
| Интерактивный чат | пользователь в UI | «разбери inbox», «спланируй неделю», weekly review |
| Фоновый запуск | Scheduler по cron/триггеру | ежедневная сводка в 9:00, дистилляция raw → wiki ночью |
| Реакция на событие | watcher/webhook | новый файл в `inbox/` → классифицировать и завести задачу |

Все три режима идут через один AgentRuntime: очередь запусков, лимит
параллельности, бюджет (max turns / max cost) на запуск, журнал в
`.forma/runs/`.

### Permissions

Запуск агента получает профиль разрешений:

- `read-only` — отчёты, аналитика (только чтение vault и MCP-read);
- `vault-write` — может править файлы внутри vault, но не bash и не внешние
  side-effects без подтверждения;
- `full` — для интерактивного чата; опасные действия (отправка письма,
  создание тикета во внешнем трекере) идут через permission_request → в UI
  всплывает подтверждение.

### Чаты и накопление знания

Каждая сессия пишет полный transcript в `chats/`. По завершении значимых
сессий запускается фоновая «выжимка»: summary.md + извлечённые решения/факты
кладутся в `raw/` — дальше их подберёт дистилляция (§5). История чатов
доступна в UI, сессию можно продолжить (resume).

## 5. База знаний: LLM-wiki контур

Двухслойная модель:

- **`raw/`** — входящий поток: заметки, transcripts чатов, выгрузки из
  интеграций (письма, тикеты), черновики. Append-only по духу, ничего не
  редактируется задним числом.
- **`wiki/`** — дистиллированные страницы: компактные, перелинкованные
  (`[[wiki-links]]`), с frontmatter `sources:` — откуда взято.

Связывает их **агент-«библиотекарь»** — встроенный кастомный агент по
расписанию (например, раз в сутки): просматривает новое в `raw/` и `chats/`,
обновляет или создаёт wiki-страницы, поддерживает `wiki/index.md`, помечает
устаревшее. Скилл `distill` — редактируемый пользователем, так что подход к
дистилляции кастомизируется.

Поиск: FTS5 по всему vault в UI + сам агент при ответах (Grep/Read по vault).
Векторный поиск сознательно не в MVP — на персональных объёмах grep+FTS+links
покрывают потребность; слот для embedding-индекса оставлен в IndexService.

## 6. Кастомные агенты

Агент — файл в `agents/`:

```markdown
---
name: weekly-report
trigger:
  type: cron            # cron | event | manual
  schedule: "0 18 * * 5"
permissions: vault-write
budget: { maxTurns: 30 }
output: reports/
---

Собери отчёт за неделю: закрытые/просроченные задачи по проектам из
projects/, ключевые решения из journal/. Сохрани в reports/weekly-YYYY-WW.md
и обнови сводку в wiki/work-log.md.
```

UI даёт форму создания/редактирования (по сути — редактор этого файла),
список запусков с логами и стоимостью, кнопку «запустить сейчас».
Scheduler — `croner` внутри forma-server; запуск = headless-сессия
AgentRuntime с этим промптом. Событийные триггеры: паттерн файлов в vault
(`inbox/*`), webhook-эндпоинт (для внешних систем).

Встроенные агенты поставляются так же, файлами: `librarian` (дистилляция),
`secretary` (утренняя сводка дня), `janitor` (просроченные задачи, напоминания).
Пользователь их видит и может править — нет «магии» в коде.

## 7. Интеграции с внешними системами

Принцип: **Forma не пишет коннекторы — пользователь подключает MCP-серверы.**

- UI настроек управляет `vault/.claude/mcp.json`: добавить сервер (stdio/HTTP),
  проверить подключение, посмотреть список инструментов.
- Секреты (токены) — не в vault: в `.env` / Keychain, в mcp.json — только
  ссылки на переменные.
- Skills (`.claude/skills/`) — сценарии поверх инструментов: например, skill
  «утренний разбор» дергает MCP почты и календаря, создаёт задачи в inbox.
- Для систем без MCP — кастомный агент с bash/HTTP-доступом или webhook-триггер.

Так «достать задачи из почты/календаря/трекера» = подключить соответствующий
MCP + включить встроенный skill, без изменений в коде Forma.

## 8. Frontend

- **React + TypeScript + Vite**, TanStack Router + Query, Tailwind + shadcn/ui.
- **Редактор — TipTap (ProseMirror)** в block-режиме: Notion-подобный WYSIWYG,
  сериализация в markdown (источник истины остаётся .md). Слэш-меню, таблицы,
  чекбоксы задач, `[[wiki-links]]` с автодополнением из индекса.
- **Дашборды:**
  - *Сегодня* — план дня из journal + задачи `scheduled: today` + сводка агента;
  - *Неделя* — календарная сетка задач и дедлайнов;
  - *Проекты* — карточки со статусом/прогрессом, внутри — kanban по задачам;
  - *Знания* — wiki с графом ссылок и поиском.
- **Чат** — постоянная правая панель (как Copilot-sidebar): стриминг ответа,
  визуализация tool-calls («агент читает projects/...»), inline-подтверждения
  permissions, история сессий. Из любого документа — «обсудить с агентом»
  (документ уходит в контекст).
- Обновления данных: SSE-канал от сервера (агент поменял файлы → индекс
  обновился → UI инвалидирует запросы). Realtime-CRDT не нужен — один
  пользователь.

## 9. Стек и структура репозитория

Монорепо (npm workspaces), TypeScript везде:

```
forma/
├── apps/
│   ├── server/        # Node 24+, Hono, node:sqlite, chokidar, croner,
│   │                  # @anthropic-ai/claude-agent-sdk, simple-git
│   ├── web/           # React, Vite, TipTap, TanStack, Tailwind
│   └── desktop/       # (позже) Tauri 2, web как фронт, server как sidecar
├── packages/
│   ├── core/          # типы домена, парсинг frontmatter, конвенции vault
│   └── agent/         # AgentProvider-абстракция + Claude-провайдер
└── docs/
```

Почему так: Agent SDK — TS-first; один язык на весь стек; встроенный
`node:sqlite` — синхронный, с FTS5 и без нативных зависимостей; Hono —
лёгкий и переносимый (пригодится в Tauri-sidecar); Tauri вместо Electron —
меньше вес, нативный WebView на macOS.

## 10. План реализации

| Фаза | Содержимое | Результат |
|---|---|---|
| **0. Скелет** | формат vault, core-пакет, server: VaultService + IndexService + REST, web: дерево файлов, markdown-редактор, список задач | можно вести базу руками через UI |
| **1. Агент** | AgentRuntime + чат в UI (стриминг, permissions, история), CLAUDE.md/skills bootstrap, дашборды «Сегодня»/«Неделя»/kanban | главный сценарий: «спланируй день/неделю», разбор inbox |
| **2. Автономия** | Scheduler, кастомные агенты + UI, журнал запусков, встроенные агенты (secretary, janitor), UI для MCP/skills | фоновые сводки, триггеры, интеграции через MCP |
| **3. Знания** | librarian-дистилляция raw→wiki, выжимки чатов, отчёты, weekly-review skill, граф ссылок | накопление знаний работает само |
| **4. Десктоп** | Tauri-обёртка, Keychain для секретов, автозапуск сервера, полировка | приложение под macOS |

## 11. Ключевые риски и решения

- **Конкурентные правки файлов** (пользователь в редакторе vs агент):
  атомарная запись через temp+rename, оптимистичная блокировка по mtime в API,
  git-коммит после каждой агентской сессии — конфликт всегда можно откатить.
  Для MVP: last-write-wins + уведомление в UI, если открытый документ изменился.
- **Стоимость и runaway-агенты:** бюджеты на запуск (maxTurns/стоимость),
  лимит параллельных сессий, отчёт по стоимости в журнале запусков.
- **Безопасность side-effects:** профили permissions (§4), внешние действия —
  только через подтверждение в UI; фоновые агенты по умолчанию не выше
  `vault-write`.
- **Vendor lock на Claude:** изоляция в `packages/agent`; формат vault и
  skills — простой текст, переносимый между агентами.
- **Производительность индекса:** на персональных объёмах (десятки тысяч
  файлов) SQLite+FTS5 с запасом; полная переиндексация — секунды.
