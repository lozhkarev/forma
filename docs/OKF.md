# Forma и OKF (Open Knowledge Format)

Решение: слой знаний Forma (`wiki/`) ведём как **OKF-bundle** (Open Knowledge
Format v0.1, GoogleCloudPlatform/knowledge-catalog). Это делает базу знаний
переносимым, самоописываемым корпусом и совместимым с экосистемой
knowledge-catalog, не меняя остального приложения.

Спека: https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md

## Что считаем bundle

- **`wiki/`** — это OKF-bundle. Его корневой `wiki/index.md` несёт
  `okf_version: "0.1"` (единственное место, где у index-файла есть
  frontmatter, §6/§11).
- **`raw/`** — исходный материал (sources), на который ссылаются страницы;
  не часть bundle, но цитируется через `sources:`.
- Задачи, проекты, чаты, агенты — вне OKF (это приложение, не корпус знаний).

## Принятые конвенции (что соблюдаем)

- Каждая не-reserved страница `wiki/*.md` несёт непустой `type` (у нас —
  `type: wiki`; значение producer-defined, консьюмер OKF толерантен к любому).
- Рекомендованные поля: `title`, `description` (одна строка), `tags`.
- Провенанс — расширение `sources:` во frontmatter (пути к `raw/…`, `chats/…`).
  OKF-секция `# Citations` допустима дополнительно для внешних источников.
- Перелинковка: относительные markdown-ссылки `[Title](other.md)` (переносимо
  по OKF) — поддерживаются и Obsidian-ссылки `[[wiki]]` (резолвер понимает оба,
  см. `packages/core/src/links.ts`).
- `wiki/index.md` — прогрессивное раскрытие по §6: секции + строки
  `* [Title](relative.md) — описание`.

## Расхождения с OKF (осознанные)

- **`type` опционален в Forma в целом** (детектируется по пути в `detectKind`),
  OKF требует его на каждой странице. Поэтому требование `type` соблюдаем
  только в слое `wiki/`, не во всём vault.
- **Bundle-root vs vault-root для абсолютных ссылок.** OKF трактует `/x.md`
  как относительный корню bundle; наш резолвер — относительно корня vault.
  Чтобы не расходиться, внутри `wiki/` используем **относительные** ссылки
  (`other.md`), а не `/…`.
- **`type` как закрытый enum.** Наш `detectKind` понимает фиксированный набор
  (`wiki|raw|task|…`); произвольные OKF-типы он игнорирует и определяет вид по
  пути. Для `wiki/` это совпадает (`type: wiki`).

## Отложено

- Жёсткая проверка conformance (линтер bundle).
- `log.md` (§7) на директорию — заведём, если понадобится история изменений.
- Описательные свободные `type` для разных видов знаний (пока единый `wiki`).

Поддерживает соответствие — агент `librarian` со skill `distill`: он создаёт
страницы по этим правилам.
